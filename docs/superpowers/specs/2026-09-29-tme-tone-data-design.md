# TME 音高与 LRC 歌词合并设计

## 目标与范围

新增 iOS 接口 `KaraokeView.parseTMEToneData(_ toneFilePath: String, _ lyricFilePath: String) -> LyricModel?`，接收两个本地文件的完整路径，同步读取 TME 音高 JSON 和 LRC 歌词，返回可交给现有 `setLyricData(data:usingInternalScoring: true)` 的模型。保持 `parseLyricData`、通用 `LrcParser`、XML/KRC 解析行为不变；不新增独立的 `onScore` 回调，沿用现有逐句 `KaraokeDelegate` 回调。该接口面向 Swift 和 Objective-C 调用方。

## 输入与转换

- 音高文件顶层为 JSON 数组，每项包含 `st`（播放位置，毫秒）、`d`（持续时间，毫秒）、`p`（音调）。字段可为示例中的数字字符串或 JSON 数字。
- 每个有效音高片段转换为一个 `LyricToneModel`：`beginTime = st`、`duration = d`、`pitch = 55 * (pow(2, (p - 32) / 12) - 1e-6)`。转换公式及 `p < 32` 无效的条件按需求执行；不根据音高片段推断单字歌词，`word` 为空，`lang` 为 `.unknown`，`pronounce` 为空。
- 专属 LRC 解析器提取 `[mm:ss.xx]` 时间行和 `[ti:]`、`[ar:]` 元数据。时间戳按十进制秒的小数位数换算为毫秒，例如 `[00:43.30]` 为 `43300 ms`；不调用或修改旧 `LrcParser.parseTime`。歌词行原文保存在 `LyricLineModel.content`，模型采用 `.lrc` 类型，以保持逐行展示。
- 解析出的 LRC 行按时间先后排序；每行的时间范围为 `[本行起点, 下一行起点)`。按照 `st` 落入的范围归属音高；跨越下一行起点的片段在边界截断，不将余下部分分给下一行。无法归属或截断后时长为零的片段不参与计分。最后一行若有音高，以最后一个有效音高片段的结束时间为有效结束点。
- 行显示顺序与原 LRC 一致。标题、词曲署名、空行，以及没有有效音高的行保留显示但不可计分；识别带时间戳的标题（根据文件中的歌名/歌手元数据）及常见以 `词：`、`曲：`、`作词：`、`作曲：`、`编曲：` 开头的署名行。落在这些行的音高片段丢弃，不转移到下一行。

## 打分与回调

完整 `LyricModel.lines` 用于歌词 UI；仅含有效音高、且不属于标题署名行的歌词行进入内部打分视图。两者的区分只由本接口产生的模型携带，不改变旧模型的打分规则。`hasPitch` 在存在至少一行可计分歌词时为 `true`，`preludeEndPosition` 指向第一行可计分歌词的开始时间。

内部仍使用现有音高比较、单音符平均、逐句平均与累计得分逻辑。无音高行不产生零分回调，也不计入总分分母。逐句 `lineIndex` 从 0 起只对可计分行连续计数，`lineCount` 是可计分行总数，回调的 `model` 仍指向原歌词行；因此 UI 可保留所有歌词行。跨句边界按半开区间处理，边界时刻只匹配下一句的音高。异步计算及主线程回调沿用当前 `ScoringMachine` 机制。

## 失败处理与验证

文件不可读、音高文件不是 JSON 数组、LRC 没有合法时间行，或处理后没有可计分音高时返回 `nil`。单条音高记录的 `st/d/p` 缺失、类型/数值不合法、`st` 或时长越界、`d <= 0`、`p < 32`、转换后结果非有限数时跳过该条，继续处理其他记录；不让溢出导致崩溃。

单元测试覆盖两位与三位 LRC 小数、音调转换（含 `p = 32`）、字符串与数字字段、片段归行和跨行截断、标题署名及无音高行的展示/排除、坏记录跳过与全坏返回 `nil`。集成测试把生成模型交给 `ScoringMachine`，验证只回调可计分行、回调索引和总行数连续、累计分与逐句分一致；另有旧 `parseLyricData` 的行为回归检查。
